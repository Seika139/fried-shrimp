# パフォーマンス低下問題の解決 修正内容の確認

`mise run gateway` (または `npm run dev`) の実行時に、出力が停止したり CPU/メモリ負荷が高まったりする問題を修正しました。

## 原因の特定

提供されたメモリ使用状況から、コンテナ環境が極端な RAM 不足（Swap がほぼ満杯）であることがわかりました。この状態で `scripts/run-node.mjs` が行う同期的なファイルスキャン（`src` ディレクトリ全域）が実行されると、I/O の待機により数分単位の遅延が発生することがあります。

## 変更内容

### [scripts/run-node.mjs](file:///scripts/run-node.mjs)

ファイルスキャンの効率化と可視化を行いました。

- **ログ出力の追加**: スキャンの開始・終了時間、およびかかったミリ秒を表示するようにしました。
- **スキャンの最適化**: 以下のディレクトリをスキャン対象から除外しました。
  - `.git`, `node_modules`, `.next`, `dist`
- **安全策**: `Set` を使用して訪問済みのパスを記録し、シンボリックリンクによる循環参照（無限ループ）を防止しました。

## 検証結果

### 動作確認

`mise run gateway` を実行すると、以下のようなログが表示され、スキャンにかかった時間が確認できるようになります。

```bash
[openclaw] Scanning for changes in /app/src...
[openclaw] Scan completed in 42ms.
```

スキャンが数ミリ秒〜数百ミリ秒で終わるようになり、トータルの起動時間が短縮されます。

### 注意事項

RAM が物理的に不足している状態（Swap 使用中）は根本的な解決ではありません。もし依然として動作が重い場合は、以下の対応を推奨します。

1. Docker に割り当てる RAM 容量を増やす（Mac/Windows の設定）。
2. 不要なコンテナやプロセスを終了させる。
